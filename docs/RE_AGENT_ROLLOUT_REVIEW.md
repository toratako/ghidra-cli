# `roll.jsonl` に見る ghidra-cli の課題

調査日: 2026-09-21。対象読者: ghidra-cli のメンテナー。

ghidra-cli の入力構文、解析情報の取得・編集、診断を対象に、RE Agent が詰まった箇所のうち未対応の課題を整理する。Agent の操作ミスも、コマンドの発見性、引数設計、結果の扱いやすさを評価する材料として残す。

## 優先度・修正案・難易度・認識すり合わせ

優先度は症状の深刻さだけでなく、再発しやすさ・CLI で解決できる範囲・費用対効果から評価した。難易度は表中の修正案を実装・検証する場合の見積もりであり、残る課題の現行版での再現試験は未実施。

- **P2**: 仕様を決めて取り組む候補。**P3**: 既存の CLI 機能・案内の見直しを優先。
- **難易度 低**: 局所的な修正や案内の整理。**中**: Ghidra との連携や出力・検証の追加。**高**: ABI の意味を保つ必要があり、対象や環境による差も大きい。
- **すり合わせ 低**: 既存の目的・仕様から修正方針を決めやすい。**中**: コマンド構成や出力形式に選択肢がある。**高**: 公開する編集能力やデータ表現の範囲を決める必要がある。これは技術調査の量とは別の評価。

| 優先度 | 課題・対応箇所 | 修正案・担当範囲 | 修正難易度 | あなたとの認識すり合わせ必要度・論点 |
| --- | --- | --- | --- | --- |
| **P2** | 引数・戻り値の格納位置の明示編集（§3） | 既存のシグネチャ・呼び出し規約編集で表現できない ABI を対象に、レジスターやスタック上の格納位置の指定を検討する。引数の既存取得機能を使い、戻り値を含む不足情報を絞る。 | **高**。隠れた引数、格納位置、呼び出し規約の組み合わせが結果を左右する。 | **高**。明示編集を必要とする対象 ABI と、格納位置の表現・指定範囲。 |
| **P3** | `doctor` から設定・起動条件を把握する導線（§1） | 設定の参照元、インストール先の解決結果、ループバック通信の失敗を診断から読み分けられるか確認する。既存の環境設定資料で説明済みの内容は、必要に応じて診断から案内する。 | **低**。診断と案内の見直しが中心。 | **低**。既存の CLI 環境診断の範囲で対応できる。 |
| **P3** | コマンドの発見性・引数と出力の扱いやすさ（§2・4） | Agent が推測した名前やオプションを材料に、コマンド構成・ヘルプ・エラー時の候補提示を点検する。自由文の入力方法と、対象・件数・フィールドを絞る入口も確認する。誤操作ごとにエイリアスを足す方針にはしない。 | **低〜中**。案内の修正か、コマンド・引数の設計変更かで異なる。 | **中**。命名、位置引数とオプションの使い分け、通常の出力量をどこまで統一するか。 |

## 確認できた詰まりと回復方法

### 1. `doctor` の設定・起動条件の診断

最初の `doctor` は、Ghidra のインストール先が見つからないことと、`doctor.loopback_bind: ... Operation not permitted` の 2 件を報告した。Agent はインストール先を指定しないまま、XDG ディレクトリを `/tmp` 配下に変更していた。その後 `/opt/ghidra` を発見し、`GHIDRA_INSTALL_DIR` を設定して権限昇格付きで再実行したところ、両方のチェックが通った。回復は確認できるが、もともとどの設定からインストール先を取得する想定だったかまではログから確定できない。[失敗、L26](../roll.jsonl#L26)、[doctor 成功、L40](../roll.jsonl#L40)。

両方の失敗は既に区別して報告できている。診断から設定の参照元・復旧手順へ辿れるかを確認する。

### 2. コマンド構文の推測による再試行

| 試した操作 | 発生した失敗 | 回復方法 |
| --- | --- | --- |
| `config show` | 未知のサブコマンド | `config --help` を確認し、インストール先は `/opt` から発見 |
| `function signature --help` | 未知のサブコマンド。CLI が `set-signature` を候補として提示 | `function set-signature --help` を使用 |
| `comment set ADDRESS --text ...` | 本文の指定方法を推測し、未対応の `--text` を使用 | ヘルプを確認し、本文を位置引数に変更して `--comment-type plate` を指定 |

根拠: [L31](../roll.jsonl#L31)、[L55](../roll.jsonl#L55)、[L110](../roll.jsonl#L110)、[L115](../roll.jsonl#L115)。
エラーには修正の手がかりがあった。推測された名前・引数は発見性の点検材料になるが、この記録だけで命名変更やエイリアス追加は決められない。

### 3. 引数・戻り値の格納位置の明示編集

4 関数の末尾が `ret 4` となっており、Agent はこれを「2 バイトの集成型を返すための隠れた出力ポインターを取り除く処理」と判断し、`__stdcall` と明示的な 4 バイトの解放量でモデル化した。これは対象固有の回避策であり、i386 プログラム全般に適用する修正規則ではない。[命令の根拠、L245](../roll.jsonl#L245)、[モデル修正、L253](../roll.jsonl#L253)。

残る検討対象は、引数・戻り値の格納位置の明示指定。この記録だけでは、その指定が必要なケースまでは確定できない。既存のシグネチャ・呼び出し規約編集で表現できない対象 ABI を絞ってから、取得・編集範囲を決める。推定結果の自動修正は含めない。

### 4. 一覧取得・検索の出力量

広範囲の一覧取得・検索で、切り詰め前に約 24 万・約 10 万 2 千トークンの出力が発生した。[L220](../roll.jsonl#L220)、[L303](../roll.jsonl#L303)。

ghidra-cli 単独の出力量の問題とは断定できないが、対象・件数・フィールドを絞る指定を発見しやすいか、結果をファイルへ保存して追えるかを点検する。

## 優先度判断に使った実装の確認

初回整理では HEAD `b5a1e54` の作業ツリーを読み取り確認した。以下は現行の作業ツリーで残る検討項目に関係する入口であり、元ログの失敗の再現試験ではない。

- **ABI と変数情報**: [CLI 定義](../src/cli/function.rs)にはシグネチャ・戻り値・呼び出し規約の編集と変数の改名・型変更が既にある。[DecompileCommands.java](../src/ghidra/scripts/ghidracli/DecompileCommands.java) は引数・変数の型、サイズ、格納位置を取得できる。引数・戻り値の格納位置を明示指定する操作はないため、既存の取得機能と重複しない編集範囲を検討する。
- **環境**: [runtime.md](runtime.md) には XDG の変更、インストール先の明示、ループバック通信の権限に関する説明が既にある。環境の問題を、未実装の解析機能として扱わない。
